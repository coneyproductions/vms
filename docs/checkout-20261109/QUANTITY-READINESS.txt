Root cause and corrected behavior

TEC's native template renders quantity zero. BVM already treated fields as totals
including existing cart tickets, but never restored those totals when TEC left zero.
A cart notice for GA 1 + Veteran 2 could therefore contradict both zero fields.
The correction explicitly restores/labels totals and reports each admission's
existing and additional quantities. The original delta calculation still submits
only increases above the cart snapshot. Continuing checkout with unchanged totals
sends no addition. Existing cart tickets are removed through Review cart.

Guest fields appear only for genuine extra claims beyond the current self allowance.
Reloads, cart return/removal/reduction, native resets/replacement, keyboard editing
and history refresh preserve that contract. Ratio caps cannot erase existing cart
visibility or enable extra tickets without qualifiers. Missing atomic configuration
blocks native submission of totals, with a meaningful Review cart error, to prevent
an unsafe fallback from replaying existing cart items.
