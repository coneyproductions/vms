Findings and corrections

1. Safari footer action race: CONCLUSIVELY reproduced as a controller/lifecycle
   mechanism, then eliminated in deterministic local Chromium and WebKit tests.
   Native Event Tickets ready/bindEvents always disables its purchase submit button,
   including its pageshow/history path. .2 also used that button for continuing an
   existing cart and did not consistently reconcile a submit-only disabled write.
   The new guarded cart-navigation link is visually the footer action but does not
   share TEC's purchase selectors. The native submit remains for actual additions.
   Native afterSetup reconciles readiness; loading, pending cart context, active
   submissions, invalid native quantities, failed extensions and checkout blockers
   remain guarded. Asynchronous guest results refresh readiness. Disabled navigation
   has no href or keyboard tab stop. The former unconditional pageshow enable is
   removed. A navigation/submission lock prevents repeated activation. Recognized
   cart changes invalidate the snapshot and reload through GET; a stale queued
   delta is rejected before transport. No arbitrary disabled attribute is globally
   force-enabled, and native/server validation is not bypassed.
   This resolves the reproduced race; physical iOS Safari with installed theme and
   real hosting has not been newly accepted. Local WebKit is not a device certificate.

2. Guest-email layout: the actual V2 surface lacked the progressive class required
   by its responsive selectors. Those selectors now apply to V2 at narrow widths.
   Input/button stack vertically with bounded widths; long labels/status text wrap.
   Desktop/tablet two-column layouts are preserved at their existing breakpoint.
   The new navigation action explicitly retains pointer access inside the existing
   sticky footer, whose parent intentionally has pointer-events disabled.

3. Amounts: existing event-ticket value, additional items and selected event-ticket
   estimate are separate. Increasing one $1 GA ticket to two shows existing $1,
   additional $1 and selected ticket estimate $2. A separate CURRENT cart total
   comes directly from WooCommerce's existing formatted total and excludes unadded
   selections. Copy identifies estimates and directs final discounts/tax/payable
   totals to cart/checkout. The PHP addition reads the total only; it does not
   recalculate prices/tax, save a cart/order, change payment logic or charge anything.
   Missing Woo/cart context says See cart instead of inventing a payable total.

4. Quantities: restored totals still have the intentional existing-cart minimum.
   Each total explanation now has a direct Reduce or remove tickets in cart link.
   Existing self/guest assignments are preserved. No negative delta or restored-total
   replay is introduced; an increase submits only the positive requested difference.
