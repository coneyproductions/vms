# G14/G15 Provenance V2

This document records the release-engineering replacement for the unrecoverable G14 byte artifacts used by the G15 ticketing date-window regression. It is developer evidence, not end-user release documentation.

## Historical issue

The historical public-release builder copied source filesystem modification times into ZIP entry metadata. Git preserves file contents and executable-mode state, but not those modification times. Thirty-five historical source-file mtimes were later lost, and a comprehensive local artifact search found no surviving copy of the original ZIP or strict Plugin Check JSON. The G14 ZIP therefore cannot be regenerated byte-for-byte from the retained source and evidence.

The original identities remain immutable chain-of-custody facts:

- source commit: `2c8f790b9128d547b8bc0a27a714253fb6671bea`
- public version and filename: `1.2.0`, `backstage-venue-manager-1.2.0-public-release.zip`
- recorded ZIP size: `2,054,980` bytes
- recorded ZIP SHA-256: `fec238a519108c7013659b4114e69e9aad93c5c6f864551d4290737d30a609e5`
- recorded strict Plugin Check JSON SHA-256: `c5fe4d23b3cdf632f239632a23f2c58f9ccf7b8e293ff4b9e71f65101527aa17`
- recorded build interval: `2026-08-08T14:56:01Z` through `2026-08-08T14:56:48Z`

The ZIP status is `original artifact unavailable / byte-identical reconstruction impossible from retained evidence`. The strict JSON status is `original artifact unavailable`. Neither recorded hash is an expected hash for newly generated output.

## G15 migration semantics

G15 now verifies the exact historical source object, the deterministic 372-file content manifest, immutable fixture schemas and hashes, the retained scan totals and 14 DateTime rows, the five-versus-nine ownership split, historical source projections, mirror/isolated-shadow constraints, and current runtime/date-window behavior.

The original ZIP and strict JSON hashes remain asserted as historical identifiers. Provenance v2 does not claim that a regenerated ZIP is the original archive and does not treat either historical hash as reproducible content identity.

## Scope and safety

This migration changes release evidence, tests, and ZIP metadata policy only. It does not change Event Plan behavior, ticket checkout, event-reschedule logic, admissions, reservations, customer data, frontend behavior, or WordPress.org prefix/identity behavior. The only shadow-tree edits used by G15 are the previously established five ticketing DateTime changes in the isolated task copy; no installed/live tree is changed.
